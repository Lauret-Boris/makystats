Validation

Contrôles numériques de makystats par rapport aux références ouvertes (surtout statsmodels) et aux conventions des logiciels classiques (vraisemblances et critères d’information façon EViews). L’objectif est la transparence pour l’enseignement et la réplication : quand les chiffres coïncident, la raison est documentée ; quand ils diffèrent, l’échelle ou la définition de la vraisemblance est indiquée explicitement.

Les chiffres ci-dessous utilisent des séries simulées (graine 42) pour que chacun puisse refaire la comparaison en quelques lignes de Python. Ce sont des illustrations, pas une certification formelle.

1. ARMA(1,1) — exact vs statsmodels

ARMA(1,1) simulé avec constante, innovations gaussiennes, n=200, graine 42. makystats utilise likelihood='exact' ; statsmodels l’ARIMA gaussien par défaut.

Grandeurmakystats exactstatsmodels ARIMA(1,0,1)
const0.92110.9210
AR(1)0.47580.4758
MA(1)0.40410.4040
σ²0.76340.7634
log-vraisemblance−257.182−257.182
 
from makystats import ARMA
from statsmodels.tsa.arima.model import ARIMA
# y = ARMA(1,1) simulé …
res = ARMA(p=1, q=1, trend="c", likelihood="exact").fit(y, verbose=False)
sm  = ARIMA(y, order=(1, 0, 1), trend="c").fit()
print(res.params, res.llf)
print(sm.params, sm.llf)

2. ARMA — vraisemblance conditionnelle (défaut)

Sur la même série, le défaut likelihood='conditional' donne une log-vraisemblance différente (burn-in), plus proche de l’ARMA conditionnel d’EViews que de la vraisemblance exacte de Kalman :

Moteurlog-vraisemblanceRôle
makystats exact−257.182Alignement statsmodels / EViews ML
makystats conditional (défaut)−255.864Style EViews conditionnel ; non gaussien OK

C’est volontaire. Utilisez likelihood='exact' pour une comparaison côte à côte avec statsmodels ; gardez le défaut pour les grilles GARCH et les innovations non gaussiennes.

Avec sélection automatique du retard sur d’autres séries, le lag retenu peut différer légèrement de statsmodels ; à retard fixé, le mapping MacKinnon d’une statistique donnée est le même. Les tests Engle–Granger suivent le même principe (voir la page Engle–Granger).

4. Critères d’information VAR — différence d’échelle

VAR(1) bivarié. La log-vraisemblance système coïncide ; l’AIC publié non, car les formules diffèrent :

Grandeurmakystatsstatsmodels
Log-vraisemblance système ℓ−399.824−399.824
AIC5.447 (−2ℓ/T + 2k/T)−0.228 (log|Σ̂| + 2k/T)
BIC5.568−0.107

makystats suit un AIC par observation, style EViews. summary() affiche aussi une ligne AIC log-det pour la comparaison avec Lütkepohl / statsmodels. Le classement des ordres de retard reste en général inchangé ; seule l’échelle absolue du critère change.

5. Conventions volontaires

  • ARMA–GARCH — réparation de domaine, bornes Student/GED et choix de backcast suivent une MLE robuste (option df= fixe façon EViews). De petits écarts de LL par rapport au paquet arch sur FIGARCH sont notés dans la doc du module.
  • Rang de Johansen — select_coint_rank utilise les p-valeurs continues MHM (1999) ; les tables de valeurs critiques restent disponibles via summarize_johansen. La décision de rang peut différer d’une règle purement CV à 5 % — la statistique de trace est partagée avec statsmodels à spécification égale.
  • ARDL — valeurs critiques des bornes (Pesaran–Shin–Smith asymptotique ; Narayan petit échantillon) intégrées ; codage des cas 1–5 conforme aux manuels.

7. ARIMA(1,1,1) — airline log-passengers

Sur log(passengers), spécification ARIMA(1,1,1) avec dérive (constante dans l’équation en différences). makystats (d=1, likelihood='exact') coïncide avec statsmodels (trend='t' après intégration, équivalent d’une constante sur les différences) :

Grandeurmakystats exactstatsmodelsEViews (capture)
const / C0.00980.00980.0100
AR(1)−0.5826−0.5826+0.7173
MA(1)0.85020.8502−1.0000
σ²0.01020.01020.0097
log-vraisemblance124.804124.804127.033

Les chiffres EViews correspondent à une estimation non convergente (message « Failure to improve objective… ») avec racine MA sur le bord (MA(1) = −1, non inversible). Ce n’est pas le maximum de vraisemblance global : en repartant de ce point en CSS/MLE, l’optimiseur revient vers la région (AR ≈ −0,58, MA ≈ 0,85) trouvée par makystats et statsmodels. Pour un ARMA (d=0) sur les niveaux en log, makystats exact et EViews ML s’alignent ; l’écart observé est spécifique à cette course ARIMA ratée dans EViews, pas à une différence de modèle dans makystats.
