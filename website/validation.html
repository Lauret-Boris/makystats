Validation Examples

Validation

Numerical cross-checks of makystats against open references (mainly statsmodels) and classical software conventions (EViews-style likelihoods and information criteria). The goal is transparency for teaching and replication: when numbers match, they should match for a documented reason; when they differ, the scale or likelihood definition is stated explicitly.

Figures below use fixed simulated series (seed 42) so that anyone can reproduce the comparison in a few lines of Python. They are illustrations, not formal certification benchmarks.

from makystats import ARMA
from statsmodels.tsa.arima.model import ARIMA
# y = simulated ARMA(1,1) …
res = ARMA(p=1, q=1, trend="c", likelihood="exact").fit(y, verbose=False)
sm  = ARIMA(y, order=(1, 0, 1), trend="c").fit()
print(res.params, res.llf)
print(sm.params, sm.llf)

2. ARMA — conditional likelihood (default)

On the same series, the default likelihood='conditional' reports a different log-likelihood (burn-in), closer to EViews’ conditional ARMA than to the exact Kalman likelihood:

Enginelog-likelihoodRole
makystats exact−257.182Match statsmodels / EViews ML

This is intentional. Use likelihood='exact' when you need a side-by-side check with statsmodels; keep the default for GARCH grids and non-Gaussian innovations.

4. VAR information criteria — scale difference

Bivariate VAR(1) on two windows of the ARMA series. System log-likelihood matches; the published AIC does not, because the formulas differ:

Quantitymakystatsstatsmodels
System log-likelihood ℓ−399.824−399.824
AIC5.447 (−2ℓ/T + 2k/T)−0.228 (log|Σ̂| + 2k/T)
BIC5.568−0.107

makystats follows an EViews-style per-observation AIC. summary() also prints a log-det AIC line for comparison with Lütkepohl / statsmodels. Ranking of lag orders is usually unchanged; only the absolute level of the criterion differs.

5. Conventions that are intentional

  • ARMA–GARCH — domain repair, Student/GED shape bounds, and backcast choices follow a robust MLE design (EViews-like fixed df= option). Small LL gaps versus the arch package on FIGARCH are documented in the module notes.
  • Johansen rank — select_coint_rank uses continuous MHM (1999) p-values; critical-value tables remain available via summarize_johansen. Finite-sample rank decisions can disagree with a pure CV rule at 5 % — the same trace statistic is shared with statsmodels when specifications match.
  • ARDL — bounds critical values (Pesaran–Shin–Smith asymptotic; Narayan finite sample) are embedded; case coding follows the textbook 1–5 scheme.

7. ARIMA(1,1,1) — airline log-passengers

On log(passengers), ARIMA(1,1,1) with drift (constant in the differenced equation). makystats (d=1, likelihood='exact') matches statsmodels (trend='t' after integration — equivalent to a constant on differences):

The EViews numbers come from a non-convergent run (message “Failure to improve objective…”) with the MA root on the boundary (MA(1) = −1, non-invertible). That is not the global MLE: restarting CSS/MLE from that point moves back to the (AR ≈ −0.58, MA ≈ 0.85) region found by makystats and statsmodels. For ARMA (d=0) on log levels, makystats exact and EViews ML agree; the gap here is specific to that failed EViews ARIMA path, not to a model mismatch in makystats.

6. How to re-run checks

pip install makystats statsmodels
python -m pytest tests/ -q -m "not slow"   # package test suite
# plus the snippets above for ARMA / ADF / VAR

For teaching packs, prefer likelihood='exact' on pure Gaussian ARMA and the log-det AIC line in VAR summary() when students compare printouts with statsmodels or textbook tables built on |Σ̂|.
